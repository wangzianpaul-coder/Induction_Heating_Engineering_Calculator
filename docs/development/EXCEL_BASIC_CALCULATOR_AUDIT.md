# 附件单方案反推计算器审计与 0.9 边界

## 1. 审计对象

- 文件：`感应线圈匹配_单方案反推计算器.xlsx`
- SHA-256：`AD5A0CA9ED77E654F6F43CA46C710F222FE6375F892E2D7871F1C1CB14A8A339`
- 工作表：`单方案反推计算器`、`逐步过程`、`说明`
- 处理方式：只读导入、公式提取、依赖检查和整表渲染；原文件未修改。

附件包含 23 个手填输入和 17 个公式输出，但没有输入数据验证。独立读取器没有成功
重算 `逐步过程` 页的部分跨表引用，并显示了 `#NAME?`；这不能据此判定原工作簿在
Microsoft Excel 中存在相同错误，也不能把缓存结果当作验证证据。

0.9 网页现有两个严格隔离的入口：三文件兼容 **基础计算器**逐项复现用户另行提供的
`index.html`、`styles.css` 和 `app.js`；**高级计算**只显示由当前受控求值器实际计算出的
步骤和状态。兼容基础页的公式、示例默认值和回归结果不进入高级 Case，也不构成工程
方法的校准或科学验证证据。完整移植边界见
`docs/development/THREE_FILE_BASIC_CALCULATOR_INTEGRATION.md`。

## 2. 可安全继承的内容

三文件兼容基础计算器沿用以下单方案工作方式；高级受控入口也保留相同的易用性原则，
但不直接继承附件的历史数值作为受控工程输入：

1. 一个页面填写一个线圈方案；
2. 先填写几何，再填写可选的同工况电气数据；
3. 将几何检查、理想极限和端口电气量分区显示；
4. 使用工程常用输入单位，并在计算边界转换为 SI；
5. 明确区分输入、计算结果、适用范围和注意事项。

附件中的轴向填充恒等式、理想长螺线管关系以及已知串联电阻/电感下的端口恒等式，
只有在当前 Calculation Basis、Calculation Contracts 和受控来源都能独立闭合时才进入
**高级受控计算**。高级入口的每条路线仍调用已经测试的工程求值器，而不是在 UI 中
重写公式。三文件兼容基础页则调用独立的兼容计算边界，专门复现所提供网页的行为。

## 3. 不得继承为高级受控公式或默认值的内容

| 附件内容 | 审计结论 | 0.9 处理 |
|---|---|---|
| 固定短线圈系数 `Kn=0.5197` | 不随几何变化，且无可复核来源 | 不进入高级默认值、公式、校准或验证目标；兼容基础页只保留三文件网页自己的可编辑示例系数 |
| 标作 Wheeler 的电感式 | 实际采用多层绕组形式，却代入单根管的径向宽度 | 不作为高级单层线圈结果；兼容页分别展示其明确标注的单层和多层公式 |
| 以 `l/D=0.4` 硬切换模型 | 当前受控依据没有这一模型选择边界 | 只在兼容页复现原三文件分支；不自动激活或推荐高级方法 |
| 直接输入等效电阻、交流电阻和目标品质因数 | 没有与几何、频率、温度、负载状态闭合 | 兼容页保留为可编辑输入；高级入口只能使用已有同工况证据，不从几何猜测 |
| 固定整流、冷却放大系数 | 来源和适用范围不明 | 兼容页保留为可编辑估算输入；不作为高级受控默认值或安全系数 |
| 固定水比热和密度 | 缺少绝对压力、相区和物性版本 | 兼容页可给出常物性算术水流估算；高级入口不据此发布自动水量或安全结论 |
| 标为“线圈电压”的结果 | 公式实际只是电抗电压分量 | 兼容页按三文件网页复现；高级入口分开显示受控端口分量并遵守其合同 |
| 工件尺寸和皮深 | 在附件主匹配链中没有参与等效负载 | 兼容页可显示皮深估算，但两个入口都不声称已据此完成耦合或负载预测 |

## 4. 数值交叉检查

用附件默认几何进行独立受控交叉检查时：

- 附件固定系数路线给出的短线圈电感约为 `30.5634 µH`；
- 当前受控有限长电流片关系在同一几何下约为 `23.1082 µH`；
- 两者相差约 `32.3%`。

这说明附件结果不能作为高级受控计算的黄金值或验收目标。高级入口只发布理想长螺线管
解析极限，并清楚标注“不是有限长实际线圈的推荐电感”。有限长自动推荐只有在原始来源、
适用域和警告策略全部冻结并通过验证后才可发布。兼容基础页会同时显示 Nagaoka、
Wheeler 和原网页分支结果；其中“推荐”仅表示兼容分支选择，不是高级工程推荐结论。

## 5. 0.9 两个入口的保护与隔离

- 兼容基础页对数值输入做有限性、正值、范围和组合检查，输入变化后实时重算；
- 兼容基础页的每个输入都有中文“是什么、怎样取得、影响什么”帮助；
- 兼容基础方案只保存 26 个输入，打开后实时重新计算，不保存或恢复旧结果；
- 兼容基础页不会读写高级 Case，高级入口也不会读取或覆盖基础方案；
- 高级入口继续执行空白语义、单位、来源、适用范围、限制和警告合同；
- 普通界面和基础 CSV 均隐藏内部方法号、决策号、快照哈希和追踪标识；
- 附件缓存输出没有被用作高级方法校准或科学验证目标；三文件网页的默认输出仅作为
  兼容回归目标锁定页面行为，不作为工程正确性的独立证据。

## 6. 结论

附件是早期交互和字段分组的有用研究证据，但不是完整、可直接发布的受控工程模型。
0.9 版本通过独立兼容基础页保留容易上手的单方案体验，同时由高级入口承载可追溯的
受控计算。尚未闭合的自动负载预测、有限长正式推荐和冷却水安全选型仅在高级入口继续
失败关闭；这不会阻止兼容基础页按用户显式输入提供原网页估算。
